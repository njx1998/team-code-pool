## 一、改云函数超时时间（唯一入口：界面）

**CLI 和 config.json 都改不了，别再试：**
- `config.json` 官方只支持 `permissions` 和 `triggers`，写 `timeout` 会被忽略（实测部署后仍是 3 秒）；
- `cli cloud functions deploy` 只有 `--env / --names / --paths / --remote-npm-install` 四个参数，没有超时；
- 本机无 tcb/cloudbase CLI 与腾讯云密钥，也没有其他写入通道。

**操作路径（开发者工具内，约 1 分钟）**

1. 打开微信开发者工具 → 载入项目 `team-code-pool`；
2. 点顶部工具栏的 **「云开发」** 按钮 → 弹出 **云开发控制台 v2.0.3** 独立窗口；
3. 左侧菜单点 **「云函数」** → 进入云函数列表（列：云函数名称 / 类型 / 函数状态 / 最后更新时间 / 创建时间 / 操作）；
4. 找到目标函数那一行（**不要点函数名链接**），点该行右侧操作栏的 **「版本与配置」**；
5. 在弹出的「配置云函数」窗口里，点开 **「▶ 高级配置」** 折叠项 —— 这里才有超时时间；
6. 高级配置里有三项：
   - **内存配置**（下拉框，如 256 MB）← 不要动
   - **执行超时**（输入框 + 「秒」字样）← 三连击选中原值，输入新数字
   - 环境变量（Key/Value）← 不要动
7. 点右下角绿色 **「确定」** 保存。保存立即生效，**不需要重新部署**，以后重新部署代码也不会覆盖。

**当前值**：`submit = 5 秒`、`purge = 25 秒`（2026-11-26 已改并验证）
**建议值**：submit 5~10 秒（用户在等，别给太长）；purge 25~60 秒（后台跑，给足时间一次删干净）

## 二、上传定时触发器（purge 每天 0 点清理）

> 背景：新版开发者工具（1.06+/2.02）的内嵌云开发控制台**没有触发器入口**；CLI 的 `cli.js` 里连 `trigger` 字符串都不存在。`config.json` 的 `triggers` 靠「上传触发器」动作推到云端，光 deploy 不会创建。

**入口 A（最快，30 秒）**
1. 开发者工具左侧资源管理器，展开 `cloudfunctions` → `purge`；
2. **右键 `config.json` 这个文件**（不是 purge 文件夹、不是 index.js）；
3. 菜单里选 **「上传触发器」**；
4. 成功后会读 `config.json` 里已写好的 `0 0 0 * * * *`（每天 00:00，UTC+8）。

**入口 B（网页版，一定存在）**
1. 浏览器打开 `https://console.cloud.weixin.qq.com/cloudbase/overview`，微信扫码登录；
2. 选小程序「组队码互助池」→ 进入环境 `cloud1-d2ga7pm5qf05ea36e`；
3. 左侧「云函数」→ 点 `purge` → 找 **「触发器」** 标签 → 新建 → 定时触发 → cron `0 0 0 * * * *` → 保存。

**cron 格式**：7 段 `秒 分 时 日 月 星期 年`，按北京时间。`0 0 0 * * * *` = 每天 00:00:00。
**验证**：次日 0 点后看 `purge` 的「日志」，出现 `[purge] 删除过期码: N` 即成功（N=0 也正常，只删 14 天前的已用/下架码）。

## 六、坑清单（踩过的都在这）

| 现象 | 真因 | 解法 |
|---|---|---|
| 找不到「上传触发器」 | 它不在文件夹右键里 | 右键 **config.json 文件** |
| `config.json` 写 timeout 没用 | 官方不支持该字段 | 只能界面改 |
| 19:05 定时清库没执行 | deploy 不建触发器 + 函数缺 node_modules | 上传触发器 + 先 npm install |
| 云函数偶发「提交失败」 | 超时 3 秒贴着冷启动上限 | 调到 5 秒 |
| 项目列表里找不到项目 | 列表记的是导入时路径，旧目录 `aiyou-team` 已改名 | `cli open` 重新注册，或删掉失效记录重新导入 |
| 模拟器报 `Cannot read properties of undefined (reading 'database')` | 模块顶层调 `wx.cloud.database()` 早于 onLaunch 的 init | 懒加载（已修） |
| 界面类问题照旧教程找不到入口 | 版本差异 | 搜「功能名 + 当前版本号」的官方社区帖，以同版本官方文档为准 |

## 七、界面操作自动化的注意事项（我用电脑操控时）

- 独立桌面开关在 `C:\Users\njx\.workbuddy\plugins\cache\workbuddy-computer-use\computer-use\<ver>\.mcp.json` 的 `CHILD_SESSION_ENABLE`（1=默认独立桌面）。改完要重启 MCP 服务进程，且需**下一条用户消息**才重连。
- 正确调用顺序：`gui_child_session_open` 拿 `session_id` → `gui_list_windows` 里出现 `window_id: "child_session"` → `create_task` 传它。不传 window_id 会报 `invalid_id`。
- GUI agent 容易乱点、乱按 alt+tab，需要给**精确坐标 + 只改哪一项**的 hint 纠偏；走偏时直接 `delete_task` 停掉。
- 用完 `gui_child_session_close` 注销，释放单机唯一名额。
