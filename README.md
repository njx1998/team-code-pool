# 组队 · 组队码互助池小程序

一个微信原生小程序的单页面工程，用来学习**界面还原、数据分层、状态交互**这三件事。

工程本身是完整的、可直接在微信开发者工具里运行的项目，但**只有前端和假数据**，不包含任何后端或真实业务跳转。

## 值得看的几处实现

### 1. 主题色收成 CSS 变量

`app.wxss` 里用 `page` 选择器定义了一整套色阶，页面样式只引用 `var()`：

```css
--brand-500: #0cae63;  /* 数字、强调 */
--brand-600: #0b8f52;  /* 实心按钮，白字 4.2:1 */
--brand-700: #0a7d4a;  /* 浅绿底上的绿字 4.7:1 */
```

换主题只改这组变量，不用动任何页面样式。每个 `var()` 都带兜底值，变量失效也不会崩。

### 2. 数据分层：页面不碰数据源

页面只调 `utils/request.js`，不关心数据来自 mock 还是接口。接入真后端时只需替换该文件的方法体：

```js
function fetchPool() {
  return new Promise((resolve, reject) => {
    wx.request({
      url: 'https://your-server.com/api/pool',
      success: (res) => resolve(res.data),
      fail: reject,
    });
  });
}
```

### 3. 「可用码置顶」的排序

```js
filtered
  .map((item, index) => ({ item, index }))
  .sort((a, b) => {
    const rankA = a.item.status === 'available' ? 0 : 1;
    const rankB = b.item.status === 'available' ? 0 : 1;
    if (rankA !== rankB) return rankA - rankB;
    return a.index - b.index;  // 组内保持原顺序，不依赖引擎的排序稳定性
  })
  .map((entry) => entry.item);
```

用 `index` 作次级排序键，避免依赖不同 JS 引擎的 `sort` 稳定性。

### 4. 举报链路（前端侧）

选理由（`wx.showActionSheet`）→ 上报码 id + 理由 → 刷新列表。真实产品在服务端还要做：累计举报数、超阈值下架、给发码人扣信用分、同一用户对同一码限报一次。

### 5. 按压反馈

`view` 做的按钮没有原生按压态，需要显式加 `hover-class`。项目里 7 个可点元素都加了。
